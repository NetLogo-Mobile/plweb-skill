# 通用版的本地安全登录

本页用于本地Python流程；ChatGPT插件使用自己的账号关联页。

首次需要登录或保存的会话失效时，AI 必须先创建一个简单的本地窗口，让用户自行输入物理实验室账号和密码。窗口只保留账号、密码（掩码）、登录按钮和一行状态说明，不创建复杂页面。可用运行环境自带的 GUI（例如 Python Tkinter）；优先使用已有系统能力。

账号密码只由本地登录辅助进程处理。AI 不得要求用户在聊天中提供密码，不得通过截图、界面自动化、DOM、可访问性树、调试器、文件、剪贴板、日志或工具输出读取输入值；不能把账号密码作为命令行参数或写入临时文件。AI 可以编写并启动辅助程序，但不能观察其敏感输入。

辅助程序按 practical-api.md 的认证协议直接向物理实验室发送 HTTPS 登录请求，并检查 HTTP 与业务 Status。密码仅在进程内存中用于当前登录，完成后清空输入，不保存密码。失败时只输出不含敏感值的错误类型；不得把原始登录响应直接打印给 AI。

登录成功后必须保存后续调用所需的 Token 与 AuthCode。优先使用操作系统凭据库；Windows 可用当前用户范围 DPAPI 加密后保存到仅当前用户可访问的应用数据文件，其他系统使用对应 Keychain/keyring。不得明文保存到项目、技能目录、同步盘或版本库；无可用安全存储时明确说明，保持当前辅助进程内的会话并停止宣称已持久保存，不退回明文方案。

后续请求由辅助进程/脚本在内部读取保存的会话并添加认证头，AI 只得到去除 Token、AuthCode、Password 等字段的业务结果。不要为了调用 API 将凭据读取后回显到聊天。服务端续发凭据时在辅助进程内更新安全存储；会话失效时重新打开本地登录窗口。提供断开/删除保存凭据的简单方式。

如果当前执行环境不支持本地窗口，说明限制并停止该登录流程；不要改成让用户把密码发给 AI，也不要未经要求部署云端登录站点。

## 多账号

将会话按物理实验室用户 ID 分别保存，不能添加第二账号时覆盖第一账号。只把昵称/用户ID等非凭据字段用于简单账号选择；由用户选择当前账号，或在已明确的任务中固定 account_id。单次批量任务在开始时绑定同一账号，整个批次内不切换。移除一个账号只删除该账号的安全凭据。多个辅助方法共用同一进程的两个工作线程和两请求信号量，不额外启动进程绕过限额。

## 本仓库实现

运行 `python scripts/login_gui.py`；仅需Python标准库与Tkinter。窗口不向终端输出敏感输入，登录完成清空密码并关闭。Windows使用当前用户DPAPI加密与受限目录权限；macOS/Linux需安装keyring并启用系统Keychain/SecretService/KWallet。无安全后端就停止持久化，不写明文。

运行 `python scripts/community_cli.py accounts` 查看非敏感账号列表，`python scripts/community_cli.py --account 用户ID forget` 删除指定账号的本地保存会话；不同区域分别保存。移除本地保存不等于调用服务端Logout。已有授权程序可从其他安全秘密来源登录，不能据此让AI随意读取用户密码。
